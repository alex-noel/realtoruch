# Owner media API contract (v1)

All management endpoints require a currently authenticated, email-verified account. Asset and idempotency identifiers are opaque; a key is scoped to the account. Supply a unique `Idempotency-Key` (1–128 URL-safe ASCII letters, digits, underscore or hyphen) per selected file. Keep it across retries and cancellation. `POST /v1/me/media` takes the raw file as its body, with `Content-Type` matching JPEG, PNG or WebP. The server enforces a 10 MiB streaming limit, 20 megapixels and 32,768 pixels per side, still images only, and strips metadata after applying orientation. It responds with `{id, state, description, display_url, thumbnail_url}`. States are `pending`, `ready`, `rejected`, `deleted`. Repeating a key returns the same asset; reuse for different bytes is a 409. Upload may return a terminal result synchronously; clients must not assume this. Status: `GET /v1/me/media/{id}` or `GET /v1/me/media/by-key/{key}`. Cancellation before an ID is known: `DELETE /v1/me/media/by-key/{key}` creates a durable cancellation tombstone even if the POST has not started. `DELETE /v1/me/media/{id}` is idempotent; deletion of an asset referenced by a draft returns 409 until the draft is saved without it. `PATCH /v1/me/media/{id}` takes `{description}` (plain text, at most 500 characters). Owner-only previews are `GET /v1/me/media/{id}/{display|thumbnail}` and require Authorization; browser clients can fetch bytes and use an object URL. A management DTO never contains storage paths or processing details.

`AdvertBody` accepts ordered `media_ids` alongside the existing ordered external HTTPS `images` list. The combined maximum is 30, with external images first followed by owned IDs in order. Every ID must refer to a ready asset owned by the caller. Legacy `images` must not contain this service's media URLs. Publishing materializes display URLs; thumbnail URLs can be obtained by replacing the final `/display` with `/thumbnail` only for owned-media URLs. Descriptions persist with assets; clients may use the description as alt text. Public `GET /v1/media/{id}/{display|thumbnail}` succeeds only while the asset is referenced by a published advert whose canonical listing is active and not hidden. Withdrawal makes the URL unavailable; account erasure removes bytes. Cache policy is no-store so moderation and erasure take effect on future requests (already downloaded bytes cannot be recalled).

Errors: 401 missing/invalid/closed session; 403 unverified or another owner's asset; 404 unavailable asset or public rendition; 409 key reused with different bytes or asset still referenced; 408 body-read timeout; 413 body exceeds 10 MiB; 415 unsupported or mismatched media type; 422 invalid image, animation, excessive dimensions or too many images. Responses do not reveal filesystem paths, source metadata or decoder errors. Derivative writes use generated keys, not client filenames. Orphaned unattached assets are eligible for cleanup after 24 hours; retries and deletion are idempotent. Storage cleanup failures remain retryable. Restore a database and matching object-store backup together, or forward-fix and rerun cleanup; do not roll back an applied migration destructively.

An interrupted request or 413 leaves a pending key that can be retried; invalid images make the key rejected, and deleted or rejected keys cannot be reused. Ready retries must carry the same bytes or return 409. Pending, rejected and deleted DTOs have null rendition URLs. Cancellation and deletion return the management DTO. Processing is limited to one concurrent upload body and decode per API process.

Configure local storage with `MEDIA_STORAGE_BACKEND=local` and a run-specific `MEDIA_DIRECTORY`; configure a browser-reachable `MEDIA_PUBLIC_BASE_URL`. GCS requires `MEDIA_STORAGE_BACKEND=gcs`, `MEDIA_GCS_BUCKET`, and the cloud dependency; no bucket is created. Production defaults to disabled media; enabling it requires GCS and an HTTPS public base. Schedule `PYTHONPATH=backend python -m realtoruch.media` (one sweep), or run `PYTHONPATH=backend python -m realtoruch.media --loop --interval 3600` for hourly sweeps with graceful shutdown under the API database role to delete unattached assets older than 24 hours. The storage service must provide durable private access and conditional creates; orphan cleanup must be monitored and retried on error.

The body-read deadline is 30 seconds once an upload receives the processing slot; an interrupted or timed-out pending upload can be retried.
