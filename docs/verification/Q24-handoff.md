# Q24 authentication forms

Implemented and locally verified 2026-11-17. Email and password fields expose explicit autofill purposes. Password reveal stays in component memory and does not store or log values; purpose changes/remounts conceal it again. Sign-in/registration validate locally with focused invalid fields and keyboard submission. Mode changes clear passwords and irrelevant feedback. Reset requires matching 12–128-character passwords, handles Enter deliberately, and clears values after use; a changed reset token remounts the form. Current-password deletion confirmation explains why its submit is disabled. Sensitive field spelling/autocorrection is disabled.

Node24 typecheck and 43 field/session tests passed. `q24-auth-20261117-02` passed 10/10 desktop/mobile browser checks: current/new autofill, local validation and focus, reveal/conceal, keyboard registration, account confirmation, retained-home links, stale links, sign-out fencing, reset-link errors and token fragment removal. The initial browser run caught two non-exact password-field selectors matching the new reveal buttons; those selectors now use exact labels. Physical password-manager/autofill behavior remains an installed-device check.

Integration review correction on 17 November 2026: a delayed reset completion previously could clear a newer login after dismissal. Completion now requires the same session revision and active link-instance ticket; the reset form is keyed by token and ticket. Four desktop/mobile browser cases and 62 link-lifecycle unit tests passed in the independent worker, including a held reset response across account creation, replaced/reopened links and valid reset completion. The final integrated Q40 profiles include this regression.
